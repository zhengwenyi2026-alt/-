# 隔空传 SkyDrop

局域网内**免服务器、拖拽即传**文件的跨平台桌面应用。一台设备点「创建房间」拿到 6 位房间码，另一台设备输入房间码加入，然后把文件拖进窗口、按「开始传送」，文件就出现在对方电脑的下载目录里——体验对齐苹果「隔空投送」，但**Windows 与 Mac 之间都能互传**。不在同一个网络时，还能挂一个自己的中继（Cloudflare / Vercel / 自建 Node）跨网段传输。

**下载站**：<https://zhengwenyi2026-alt.github.io/-/> ｜ **Release 与安装包**：<https://github.com/zhengwenyi2026-alt/-/releases/tag/v1.0.4>

> 命名说明：「隔空投送 / AirDrop」是 Apple Inc. 的注册商标，本项目与之**没有任何关系**，不使用、也不逆向任何 Apple 私有协议。隔空传 / SkyDrop 是一个独立的原创名称与实现。

## 核心特性

| 能力 | 说明 |
| --- | --- |
| 零服务器 | 局域网模式下两台设备直连，不经过任何云端中转，文件不出局域网 |
| 零安装依赖 | 打包成自包含的 `.dmg` / `.exe`，双击即用，无需 Node、无需 Python |
| 房间码配对 | 6 位码（剔除 I/O/0/1 易混字符），输入即可连接，不用记 IP |
| 自动发现 | UDP 组播 + 广播探测，「附近房间」列表自动出现，可点选加入 |
| 手动地址兜底 | 跨网段 / 禁用 UDP 的环境，可直接填 `IP:端口` 连接 |
| **跨网段传输** | 可选：挂一个自己的 WebSocket 中继（Cloudflare / Vercel / 自建 Node），不同 Wi-Fi、不同城市也能传，界面里只要填一个域名 |
| **本机 ngrok 隧道** | 可选：这台电脑装了 ngrok 时，服务商列表里才多出一项「ngrok · 本机隧道」——应用在本机回环起一个中继、让 ngrok 给它一条公网 https 地址，把地址发给对方即可跨网，**不用部署任何东西**；没装 ngrok 时界面上不出现这一项 |
| 拖拽传送 | 文件、文件夹均可拖入；文件夹保留目录层级递归传输 |
| **传送文本** | 第 4 步直接输入文字发给对方：**仅文本**即时出现在对方文本栏、一键复制；也可**生成 TXT**，像普通文件一样走确认与落盘流程。上限 32 KB/条 |
| 接收方确认 | 主机收到连接请求需点「允许」，发送文件需对方点「接收」，防误传 |
| 完整性校验 | 两端各自单遍增量 sha256，落盘后比对，不一致直接判失败 |
| 断点安全 | 先写 `*.part` 临时文件，校验通过再原子改名；重名自动加 ` (1)` |
| 实时进度 | 每个文件与总任务的字节数、速率、剩余时间，逐条刷新 |
| 本机传输面板 | 浏览器打开 `http://localhost:47830/` 看全量数据：逐文件字节数与进度、实时速率与剩余时间、累计统计、引擎参数、历史记录，5 语言可切，只有本机能访问 |
| 传输记录 | 本地保留最近传输历史，可一键在访达 / 资源管理器中显示 |
| 多语言界面 | 简体中文 / 繁體中文 / English / 日本語 / 한국어，跟随系统语言，可在界面即时切换、无需重启 |
| 跨平台 | macOS（Apple Silicon + Intel）、Windows 10/11（x64） |

## 三步用法

以「A 把文件传给 B」为例，两台电脑连同一个 Wi-Fi / 同一路由器。

**1. B 创建房间**
打开隔空传 → 第 1 步「创建房间」→ 点「创建房间」。界面出现大号房间码，例如 `K7M-3XQ`（实际是 6 位，中间横线仅为方便阅读）。

**2. A 加入房间**
打开隔空传 → 第 2 步「加入房间」→ 在 6 格输入框里敲 `K7M3XQ` → 点「加入房间」。
（也可以点「扫描附近房间」直接看到列表点选，或在「高级」里填 `192.168.x.x:47810` 手动连。）

**3. B 允许，A 拖文件**
B 的屏幕右下角弹出「某设备想加入房间」→ 点**允许**。
A 把文件/文件夹拖进第 3 步的虚线区域（或点「选择文件」）→ 确认目标设备 → 点**开始传送**。
B 弹出「某设备想发送 3 个文件（共 128 MB）」→ 点**接收**，进度条开始跑，完成后文件出现在 B 的 `~/Downloads/隔空传`（Windows 为 `%USERPROFILE%\Downloads\隔空传`）。

反向传同理：房间是双向通道，连上之后任何一方都能发。

**传文字不用选文件**：第 4 步「传送文本」里直接打字，点**仅文本发送**——文字立刻出现在对方的文本栏里，对方点「复制」就能拿走，全程无需确认；点**生成 TXT 发送**则把文字落成一个 `文本 日期时间.txt`，之后和传普通文件完全一样（对方点「接收」、存进保存目录）。发送过的文本两端都保留最近 60 条记录，长文本在列表里折叠成 400 字、点击展开全文。

**不在同一个网络？** 三步完全一样，只是多两件事：两台设备先在主界面右侧的 **「跨网传输」** 卡片里填同一个中继地址（需自己部署一次，见 [relay/README.md](relay/README.md)；装了 ngrok 就不用部署，见下文），然后访客可以点「经中继加入」——或者什么都不点，直接输房间码，局域网找不到人时应用会自动改走中继。细节见[跨网段 / 互联网传输](#跨网段--互联网传输)。

## 界面语言

支持 5 种界面语言：**简体中文、繁體中文、English、日本語、한국어**。

- **自动跟随系统**：首次启动读取系统 locale（`zh-TW`/`zh-HK`/`zh-Hant` → 繁體，其它 `zh*` → 简体，`en*`/`ja*`/`ko*` → 对应语言，无法识别时默认 English）。
- **随时切换**：点顶栏的「文」按钮（或设置面板里的「语言」下拉），选中立即生效，正在进行的传输不会被打断，也不需要重启应用。
- **只影响本机**：语言是本地设置，不会随连接传给对方；两台设备可以各用各的语言互传。
- **面板独立一档**：本机传输面板右上角的语言下拉默认跟随应用内当前语言，手动选过一次之后记在浏览器 `localStorage`，只改这个网页，不动应用界面。
- **保存目录跟随语言**：简体中文环境下默认落到 `~/Downloads/隔空传`，其它语言落到 `~/Downloads/SkyDrop`（Windows 为 `%USERPROFILE%\Downloads\…`），已经手动改过的目录不受影响。

实现上以**中文原文作为词典 key**（`src/common/i18n.js`）：

```js
t('已连接：{name}', { name: peer.peerName })   // en → "Connected: Mac"
```

这样带来三个好处：漏译只会退化成中文而不会出现空白；主进程只发「原文 + 参数」，译文完全由渲染层生成，所以切语言不用重启；带变量的句子用 `{param}` 占位，避免把一句话拆成三段拼接。

## 界面说明

窗口按流程分三块，右侧是设备信息，底部是记录。

- **第 1 步 · 创建房间**：大号房间码 + 「复制」按钮、「停止房间」；下方显示数据端口、本机局域网 IP 列表、「手动地址」提示、已连接设备数；开了跨网传输时还会多一行「房间已通过中继开放」。
- **第 2 步 · 加入房间**：6 格房间码输入框（自动过滤非法字符、自动跳格、可粘贴 `abc-123` 这种带横线的）、「高级：手动填 IP:端口」、「扫描附近房间」列表（显示设备名、房间码、IP、是否已开房间）；开了跨网传输时输入框下方出现「经中继加入」。
- **第 3 步 · 传送文件**：拖拽区、已选条目列表（文件名、大小、目录展开后的文件数）、「发送到」设备多选片（经中继的设备带「中继」小标签）、总大小与「开始传送」。
- **第 4 步 · 传送文本**：多行输入框 + 「仅文本发送」「生成 TXT 发送」两个按钮；下方是已收发的文本列表（方向、对端、大小、时间），每条带「复制」按钮（写入系统剪贴板），长文本折叠 400 字、点击展开，「清空文本」一键清列表。发送目标与第 3 步共用同一组设备多选片。
- **传输中**：每条任务一个卡片，含总进度条、单文件进度、当前速率、剩余时间、成功/失败标记。
- **最近记录 + 保存目录**：历史条目（方向、文件名、大小、时间、校验结果），「在访达中显示」「打开保存目录」；保存目录可自定义。
- **浮动请求卡**：加入请求、接收请求，带「允许 / 拒绝」「接收 / 拒绝」。
- **跨网传输卡片**（主界面右侧，不在 ⚙ 设置里；点「对方不在同一网络？经中继加入」会自动滚到这里）：「允许通过互联网连接」开关 + 服务商（Cloudflare / Vercel / 自建 / 检测到 ngrok 时多出的「ngrok · 本机隧道」）+ 中继地址 + 测试连接 + 隧道面板（**固定地址（可选）** 输入 / 启动 / 停止 / 地址 / 复制 / 状态）+ 实时中继状态。
- **设置**（右上角 ⚙）：设备名、语言、保存目录、是否自动接收文件、是否自动允许加入、是否允许公网地址连接、**本机传输面板地址**（只读 + 「复制」+「打开」）。

## 本机传输面板

应用启动时会额外开一个**只监听 `127.0.0.1` 的 HTTP 服务**（默认 `http://localhost:47830/`，被占用时顺延，实际地址写在设置面板里，旁边有「复制」「打开」）。房间的数据端口本身也带同一个页面，所以浏览器直接打开 `http://localhost:47810/` 看到的也是它。

它存在的理由很简单：窗口里一次只显示一两条任务、字段按「够用」裁剪，而排查问题时想要的是**全量数据**——每个文件传到哪一字节、速率掉没掉、哪个文件出错、存到了哪个目录、引擎现在按什么参数在跑。这些数据本来就在主进程内存里，单独渲染一页比塞进窗口清楚。页面每 1 秒读一次引擎快照，右上角可以**暂停刷新**（想截个干净的图或盯住某一瞬间时用）。

| 区块 | 内容 |

### 谁能访问

房间的数据端口绑在 `0.0.0.0`（局域网里的设备要连它），所以面板做了两层判断，**来源地址是回环**且 **`Host` 头是本机名字**，缺一不可：

| 请求 | 结果 |
| --- | --- |
| 本机浏览器打开 `http://localhost:47830/`、`http://127.0.0.1:47830/`、`http://[::1]:47830/` | 正常返回页面与数据 |
| 局域网其它设备访问 `http://你的IP:47830/` | **连不上**——面板端口只绑 `127.0.0.1`，从没监听网卡地址 |
| 局域网其它设备访问房间数据端口 `http://你的IP:47810/` | 仍旧是加面板之前的 `404 SkyDrop`，一个字节都不给 |
| 本机浏览器访问房间数据端口 `http://localhost:47810/` | 返回面板（与 47830 同一份页面） |
| 某个把域名解析到 `127.0.0.1` 的第三方网页（DNS 重绑定）带着 `Host: evil.example.com` 打过来 | `404 SkyDrop`，Host 白名单拦掉 |

其余边界：

- 页面 CSP 是 `default-src 'none'; script-src 'self'; style-src 'unsafe-inline'; connect-src 'self'`，不加载任何外部资源，断网、没有 CDN 也能用。
- 前端只用 `textContent` 写动态值：文件名、设备名、路径都来自对端，属于不可信输入，走 `innerHTML` 就等于让「对方发一个带脚本的文件名」变成 XSS。
- **面板没有鉴权**——它假设「能在这台电脑上开浏览器的人就是这台电脑的主人」。同一台机器上的其它进程读这些 JSON 是允许的，这和它们本来就能读你的下载目录是同一件事；跨出这台机器就不行了。
- 面板只读，不能从网页上发起传输、批准加入或改设置；所有写操作仍然只在应用窗口里。
- 端口从 `47830` 起顺延（最多试 13 个），以设置里显示的那条地址为准。

## 跨网段 / 互联网传输

同一 Wi-Fi 下不需要它。只有当两台设备**不在同一个局域网**（公司网段隔离了组播和端口、或者一个在家一个在公司）时，才需要「跨网传输」。

它的工作方式是：找一台两边都连得上的机器做**字节中继**，房主预先挂几条连接上去等，访客拨同一个房间码，中继把两条缝一起然后原样搬字节——上层的文件协议完全不知道自己在中继后面，所以**接收确认、进度、sha256 校验、目录递归和局域网下一模一样**。

```
 房主（家里）                     你的中继                     访客（公司）
 3 条 role=host 连接   ─────►   /room/<房间码>   ◄─────   1 条 role=guest
                                 配对后双向透传
```

### 五分钟上手

1. 按 [relay/README.md](relay/README.md) 部署一个中继（**推荐 Cloudflare Workers**：免费、自带 HTTPS 域名、不用买服务器，两条命令搞定）。
2. 两台设备各自在主界面右侧找到 **「跨网传输」** 卡片：勾上「允许通过互联网连接」→ 选服务商 → 填中继地址 → 点**测试连接**（这一步不需要对方在线，收到中继握手就算通过）。
3. 房主点**创建房间**，把 6 位房间码告诉对方。
4. 访客在房间码输入框下面点**「对方不在同一网络？经中继加入」**，输入房间码。局域网发现、手动 IP 那两条路此时都不用管（直接按平时的「加入房间」也行，同一网段找不到时会自动升级成走中继）。
5. 之后和平时一样：房主点「允许」，发送方点「开始传送」，接收方点「接收」。设备名旁边出现「互联网中继」标记说明这条链路走的是外网。

### 不想部署中继：用本机 ngrok 隧道（装了才出现）

ngrok 把「部署一台公网中继」压成一次点击。应用启动时会在本机常见安装位置找一次 `ngrok`：**没找到就什么都不显示**——服务商列表里没有这一项，界面和以前完全一样；找到了才多出「ngrok · 本机隧道」。

1. 房主在**跨网传输**卡片里把服务商选成 **ngrok · 本机隧道**（选它会自动打开「允许通过互联网连接」）→ 点 **创建房间** → 点 **启动隧道**。
2. 应用在 `127.0.0.1` 的随机端口上起一个内置中继（就是 `relay/node-server.js` 那份代码，不对外监听），拉起 `ngrok http <那个端口>`，拿到一条 `https://xxxx.ngrok-free.app`，自动填进本次会话的中继地址并挂上 3 条槽位。面板上点 **复制**，把地址发给对方。
3. （可选，推荐）在 **固定地址（可选）** 里填你在 ngrok 控制台「Domains」领到的保留域名，再启动隧道——地址从此不变，对方存一次以后就不用每次找你要。隧道运行中这个输入框是锁住的，改域名要先「停止隧道」。
4. 对方在**自己**的「跨网传输」卡片里选 **自建 / 其它**、把这条地址粘进 **中继地址**、点 **测试连接**（通了说明对方确实能从公网摸到你这台机器），然后在房间码输入框下点 **「对方不在同一网络？经中继加入」**，输 6 位房间码。
5. 之后与平时的跨网传输一模一样：房主点「允许」、发送方点「开始传送」、接收方点「接收」，设备名旁出现「互联网中继」标记。

前置条件与注意事项：

- 需要 **ngrok 3.x** 和一个免费账号：macOS `brew install ngrok`、Windows `winget install ngrok.ngrok`，然后 `ngrok config add-authtoken <你的 token>`。没登录时 ngrok 报的那句英文原文会被翻成这条可直接照抄的命令显示在界面上。
- **不填固定地址时地址是临时的**：ngrok 免费版每次分配的域名都不一样，所以这条地址**不会存进设置**——停止隧道或退出应用即丢弃，下次要重新点「启动隧道」并把新地址发给对方。
- **想要固定入口就填保留域名**：ngrok 免费账号也能在控制台「Domains」领一个 `xxx.ngrok-free.app` 的保留域名，填进「固定地址（可选）」后每次启动隧道都是同一条地址，对方粘一次即可长期复用。填了不属于本账号的域名（或自己想的子域名）时，ngrok 的 `ERR_NGROK_313` 之类英文报错会被翻成「这个固定地址用不了／这个域名不在当前 ngrok 账号名下」这样能照做的提示，隧道不会带着半死状态挂在界面上。
- 免费版**同时只能开一条隧道**；本机已经有别的 ngrok 在跑（或 4040 检查端口被占用）时会明确报出来，不会静默卡住。
- 隧道只为「服务商 = ngrok」这件事存在：切到别的服务商、点「停止隧道」或退出应用，ngrok 子进程与本机中继都会被收掉。
- 流量仍然经过 ngrok 的公网边缘节点透传，**没有端到端加密**，与用第三方中继同一层风险，见[隐私提醒](#隐私提醒)。

### 行为细节

- **默认关闭**：只有你自己填了地址并打开开关，应用才会向外拨连接；不打开时和以前完全一样，一个出站请求都没有。
- **3 条预开槽位**：房主侧固定挂 3 条连接等访客，用掉一条立刻补一条，所以房主不需要知道什么时候有人来；中继断线按 1/2/4/8/15 秒退避重连，界面上会显示「中继连接中断，正在重试」。
- **不会因等待而掉线**：客户端每 25 秒发一次 WebSocket ping，专门顶住「对方还在点接收、链路上没流量」这段时间（Cloudflare 约 100 秒无流量就会掐连接）。
- **房间码是唯一凭据**：中继只按房间码缝连接，猜错码的人只会拿到「中继上没有这个房间」；同一房间码挤超过 16 条待配对连接时会被 `slot-limit` 挡掉。
- **局域网优先**：跨网传输打开后，同一网段内的设备仍然走直连（更快）——访客输房间码时照旧先做一轮 2.5 秒 UDP 发现，只有发现不到人且中继可用，才自动升级成「经中继加入」并提示你一声；房主侧同理，局域网进来的连接和经中继进来的连接在列表里分开标注。
- **ngrok 的地址只活在本次会话**：`relayUrl` 存盘时按服务商区分，服务商是 ngrok 时应用不会把那条公网地址写回设置（重启就失效的地址存下来只会误导）；同理，启动时读到 `relayProvider=ngrok` 会把存量的 `relayUrl` 清空。

### 各种中继的差别（详见 [relay/README.md](relay/README.md)）

| 中继 | 可靠性 | 说明 |
| --- | --- | --- |
| Cloudflare Workers | **推荐** | 每个房间码一个 Durable Object，配对状态跟着房间走；免费额度够用 |
| 自建 Node | **推荐** | 一条 `node relay/node-server.js` 就能跑；想要端到端可控就选它，记得套一层 `wss://` |
| 本机 ngrok 隧道 | 免部署 | 零配置，但地址每次都不一样、免费版只能开一条隧道、流量过第三方边缘节点；适合临时拉一次，不适合长期挂房 |
| Vercel | 一般 | 平台模型决定了两条连接可能被投到不同实例，实例间不共享内存，运气不好会报「中继上没有这个房间」；函数还有最长执行时间限制。临时救急可以，长期用建议前两种 |

### 隐私提醒

中继是**字节透传**，所以中继运营方（Cloudflare、Vercel、ngrok 或那台机器的 root）理论上能看到传输的文件内容与文件名——这一层目前**没有端到端加密**。传敏感文件请优先用局域网或自建中继，或只在信任的双方之间使用；中继代码本身不写盘、不记日志，配对关系只存在内存里，任一端断开立刻清除。用 ngrok 时同理，而且那条公网地址本身就是凭据的一部分：拿到它的人都能试着连你的本机中继（仍然要猜对 6 位房间码，猜错只会收到「中继上没有这个房间」），地址一旦不再使用就点「停止隧道」丢掉。

## 工作原理

```
   A（发送方）                                 B（主机 / 接收方）
 ┌──────────────┐   ① UDP 组播/广播查询      ┌──────────────┐
 │  Electron    │ ─────{m:skydrop1,          │   主进程     │
 │  渲染进程    │        a:find,room:K7M3XQ}─▶│   Hub        │
 │  (拖拽/进度) │ ◀───{a:here, ip, port}─────│              │
 └──────┬───────┘        ② 应答              └──────┬───────┘
        │                                           │
        │  ③ WebSocket 连接 47810~47822             │  TCP 监听
        └────────────▶ ws (JSON 控制帧) ◀───────────┘
                     {type:hello/offer/chunk...}
        └────────────▶ 二进制数据帧（256 KB/帧）◀───┘
```

分层实现（`src/main/engine/`）：

| 模块 | 职责 |
| --- | --- |
| `roomCode.js` | 32 字符集、`crypto.randomBytes` 按 5 bit 均匀取样生成 6 位码；输入清洗与 `ABC-123` 展示格式 |
| `net.js` | 枚举非回环 IPv4 接口、按接口算广播地址、私网判定、Wi-Fi/en0 优先排序 |
| `protocol.js` | 协议版本、256 KB 分片、12 字节二进制头（`uint32 fileId + uint64 offset`）、单条文本 32 KB 上限、文件名/相对路径净化、重名改名 |
| `files.js` | 把拖入的路径展开成条目；递归目录、跳过 `.DS_Store`/`Thumbs.db`/`desktop.ini`、防符号链接成环、上限 5000 文件 / 16 层深度 |
| `peer.js` | 单台设备的会话状态机：hello 握手 → offer → 等待接收决定 → 逐文件流式发送（8 帧流水线）→ 等待落盘回执；接收侧对称处理；文本走 `text` 控制帧即时送达（无需对方确认）；增量 sha256 |
| `relay.js` | 中继**客户端**：地址归一化（`parseRelayBase`）、拨号并等 `paired`（`dialRelay`）、房主侧 3 槽位池 + 退避重连（`openRelaySlots`）、连通性探测（`probeRelay`）、25 秒 ping 保活 |
| `hub.js` | 总编排：起/停房间、TCP 监听、UDP 发现应答与探测、加入请求审批、Peer 生命周期、把内部事件摊平成 UI 事件、状态快照 |
| `dashboard.js` | 本机传输面板的服务端：回环地址与 `Host` 头双重判定、`/`、`/panel.js`、`/i18n.js`、`/api/state` 四条路由、把 Hub 状态整理成可 JSON 化的快照（含累计统计与引擎参数）、只绑 `127.0.0.1` 的常驻端口服务 |
| `panel.js` | 面板前端（无框架）：每秒拉一次快照，按概览 / 传输任务 / 设备与连接 / 历史 / 统计 / 参数六块渲染，5 语言下拉与暂停刷新，全部动态值走 `textContent` |

中继**服务端**不在 `src/` 里，而是与 app 完全解耦的 `relay/` 目录：一份运行时无关的配对状态机 `pairing.js`，加三份薄适配层（Node / Vercel / Cloudflare），部署与排错见 [relay/README.md](relay/README.md)。

关键设计点：

- **房间码即寻址**：查询包带 `room` 字段，只有开了这个房间的设备应答，避免同网段多台设备串台。
- **端口顺延**：数据端口从 `47810` 起，被占用就 `+1` 重试，最多 13 个（到 `47822`）；实际端口通过 UDP 应答告知对方，所以不用手工配置。
- **发现三重兜底**：UDP 查询先广播（全网卡广播地址 + 受限广播 + 组播组），约 0.9 秒后补发一轮并对每块真实网卡所在的 /24 网段**逐个地址单播探测**——广播被 AP 隔离或组播过滤拦掉时，单播通常仍能打通；任何一路发送失败只丢这一发，不会中断整场发现。都找不到时，加入失败提示会指向「高级 → 手动地址」。
- **控制/数据同通道**：文本帧走 JSON 控制信令，二进制帧走文件分片，传文件不需要额外开端口。数据端口上那个 HTTP 服务只有一件事：本机浏览器来要面板时给页面，其它来源一律 `404 SkyDrop`（另有一个只绑 `127.0.0.1` 的常驻端口，房间没开时面板也能看）。
- **消息严格串行**：`peer.js` 用一条 `_msgChain` 顺序处理入站消息，避免并发写文件造成的偏移错乱。
- **中继对协议透明**：中继只认 `hello-ack` / `paired` / `error` 三种控制帧，配对完就纯搬字节，所以文件协议改版不用动中继；反过来说，中继也不需要理解任何文件内容。
- **渲染节流**：进度事件按 120 ms 间隔合并上报；渲染侧用 `setTimeout` 合帧而不是 `requestAnimationFrame`——窗口被遮挡时 rAF 会停摆，导致确认弹窗画不出来。

## 网络与防火墙

| 用途 | 协议 | 端口 |
| --- | --- | --- |
| 局域网发现 / 房间码查询 | UDP | `47812`（固定） |
| 文件数据通道 | TCP（WebSocket 裸升级） | `47810`–`47822`（被占用时顺延） |
| 本机传输面板 | TCP（HTTP） | `47830`–`47842`（被占用时顺延），**只绑 `127.0.0.1`，防火墙无需放行** |
| 跨网中继（可选，仅出站） | WSS / WS | 目标中继的 `443` 或自建端口，**不需要放开本机入站** |

首次运行时的放行：

- **macOS**：弹出「是否允许接收传入网络连接」→ 点「允许」，否则对方无法加入你的房间。
- **Windows**：安装包安装时会弹一次 UAC，用 `netsh` 给应用加好入站/出站放行规则（取消也不影响安装，届时防火墙会在应用首次监听时再弹窗问一次 → 勾选**专用网络**即可）；便携版没有安装器，直接靠首次监听时的弹窗。
- 用了跨网传输时，出站方向是普通 HTTPS/WSS，一般不需要任何防火墙配置；只有强制 TLS 审计的企业代理可能挡掉，这时换 `ws://` 的自建中继或换网络。

路由器侧注意：

- 局域网模式需要两台设备在**同一二层网段**。部分开了「AP 隔离 / 客户端隔离」的公共 Wi-Fi 会屏蔽设备互访，这种情况下任何局域网工具都传不了——正是跨网传输要解决的场景。
- 加入时会自动做三重探测（广播 → 补发广播 → 所在网段逐个单播），所以轻度拦广播的网络往往也能自动连上；彻底禁 UDP 的环境再用「高级 → 手动填 IP:端口」跳过发现步骤。

## 安全模型

- **默认不出本机**：跨网传输默认关闭，关闭时应用没有任何出站连接；开启后也只连你自己填的中继域名。
- **只接受私网地址**：局域网模式下默认拒绝公网来源的直连（`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`::1/fc00::/7`），「允许公网地址」是另一个需要单独勾选的开关。
- **双向人工确认**：加入房间要主机点「允许」（经中继的请求同样要确认），发送文件要接收方点「接收」，180 秒无人确认自动超时。
- **房间码抗暴力**：6 位 × 32 字符集 = 约 10 亿种组合；同一 IP 连续输错 8 次直接拉黑，不再应答。中继侧同理——每条中继连接的输错尝试各自计数，不会一个人乱试就锁死别人。
- **路径穿越防护**：所有文件名与相对路径经过 `sanitizeName` / `sanitizeRel`——剔除 `..`、绝对路径、Windows 保留名（`CON`、`NUL`、`COM1`…）、控制字符，单段相对路径（防止只传一个 `../../x`）直接拒绝，超长名截断到 180 字符。落盘路径最终还会 `realpath` 校验，越出保存目录即拒绝。
- **无 XSS 面**：渲染进程只用 DOM API 写 `textContent`，任何来自网络的字符串都不会进 `innerHTML`。本机传输面板的前端同理，并且 CSP 为 `default-src 'none'; script-src 'self'`，不加载任何外部脚本。
- **面板只给本机**：传输记录里含文件名与保存路径，所以面板要求「来源地址是回环 + `Host` 头是本机名字」两个条件同时成立；面板端口只绑 `127.0.0.1`，局域网侧访问房间数据端口仍然是原来的 `404 SkyDrop`，DNS 重绑定被 Host 白名单挡住。详见[本机传输面板](#谁能访问)。
- **上下文隔离**：`contextIsolation: true` + `sandbox: true` + `nodeIntegration: false`，渲染进程通过 `preload` 暴露的白名单方法调用主进程；页面 CSP 关闭外链加载，主进程拒绝一切导航。
- **资源上限**：单房间最多 8 台设备、单任务最多 5000 个文件、目录递归最深 16 层、WebSocket 单帧上限 `256 KB + 4 KB`；中继侧另有槽位上限（同一房间码最多 16 条待配对连接，超出报 `slot-limit`）。
- **完整性**：发送端与接收端各自独立算 sha256，落盘后比对，不一致则删除临时文件并标记失败，不会留下「看起来成功」的坏文件。

传输内容**未加密**（同 AirDrop 的局域网直连场景，链路在你自己的路由器内）。若在不信任的 Wi-Fi 上使用，请自行套 VPN，或把它当作仅传非敏感文件的工具。

> **走中继时多一个信任对象**：中继做的是字节透传，因此中继的运营方（Cloudflare、Vercel 或那台机器的管理员）**理论上能看到文件名与文件内容**。本项目的中继代码不写盘、不记日志、配对关系只存内存且断开即清，但这不等于加密。传敏感文件请优先用自建中继；端到端加密是后续项，当前版本尚未实现。

## 性能实测

同机双实例回环、64 MB 单文件（`test/throughput.js`），多次运行最好成绩约 **264 MB/s**，典型值 230 MB/s 上下（受当时磁盘与 CPU 调度影响）：

```
node test/throughput.js 64           → 64 MB / 0.28 s ≈ 229.4 MB/s
```

流水线优化前后对比：串行等待每帧 ACK 时约 16 MB/s，改为 8 帧并发在途（`SEND_PIPELINE = 8`，约 2 MB 缓冲）后提升到 260 MB/s 以上。真实 Wi-Fi 下的瓶颈是无线带宽——5 GHz Wi-Fi 6 通常能跑满 300–600 Mbps（约 40–75 MB/s），千兆有线可稳定在 100 MB/s 以上。

同一台机器上再插一个中继（`node test/throughput.js 64 --relay`，即「发送方 → 本地中继 → 接收方」两跳，与直连同一轮跑出）：

```
node test/throughput.js 64 --relay   → 64 MB / 0.33 s ≈ 191.6 MB/s
```

也即**中继本身只带来约 16% 的开销**，纯字节搬运没有额外编码/缓冲惩罚。跨网段的真实速率与这个数无关，瓶颈完全在中继的出口带宽与两端的接入带宽上——Cloudflare / Vercel 的共享出口通常给到几十 Mbps 量级，传几百 MB 请预留时间，或直接改用自建中继。

本机传输面板开着时的实测（同机双实例、1.3 GB / 28 个文件、面板每秒轮询一次 `/api/state`）：传输中途面板读到 **465 MB/s**，整场跑完面板统计里的峰值速率 **500 MB/s**，sha256 校验一致，页面控制台无报错。面板的读取只是把内存里的状态序列化成 JSON，不占传输通道，也测不出速率衰减。

## 开发与打包

```bash
npm install            # 装 electron / electron-builder / puppeteer-core / ws（中继也复用这份 ws）

npm start              # 开发模式直接跑，改代码后重启即可
npm test               # 引擎单元测试（21 个用例，含 6 条跨网中继用例）
npm run speed          # 吞吐基准（64 MB 回环）
npm run speed -- --relay   # 同一轮加一个本地中继，量化两跳开销
npm run e2e            # 双实例真实 UI 端到端（含本地中继跨网段阶段）+ 截图到 out/e2e/

npm run dist           # 当前平台全部产物
npm run dist:mac       # 只出 dmg（arm64 + x64）与 zip
npm run dist:win       # 只出 exe（NSIS 安装版 + 便携版）
npm run release        # 打包 mac + win，并把安装包收进 可执行文件/
npm run clean          # 删掉 dist/out，回报释放了多少 MB
```

### 本地跑中继

跨网中继不进安装包，测试时单独起一个即可（`ws` 已在根目录装好）：

```bash
node relay/node-server.js --port 8790 --host 127.0.0.1   # 自建中继，health: /health
cd relay && npm run dev:cloudflare                        # wrangler dev，本地模拟 Durable Objects
```

部署到 Cloudflare / Vercel 的完整步骤见 [relay/README.md](relay/README.md)。

### 在 macOS 上打 Windows 包

electron-builder 26 已改用原生方式给 Windows 可执行文件写图标与版本信息，**本机没有 wine 也能直接出 exe**（实测：`隔空传.exe` 的资源目录从原始 Electron 的 99,072 字节增长到 185,773 字节，即图标 + 版本信息已写入）。

```bash
npm run dist:win        # 直接可用
```

如果换到旧版 electron-builder 报 `wine is not installed`，两种解法：

```bash
# 方案一：本机装 wine（约 1–2 GB）
brew install --cask wine-stable

# 方案二：交给 CI（零本地依赖）
# 自己加一个 .github/workflows/*.yml，用 windows-latest 跑 npm run dist:win 即可
```

### 在 Windows 上打 macOS 包

不行——`dmg`/`icns` 打包依赖 macOS 的 `iconutil` 等工具，跨平台方向只能 Mac → Win，不能 Win → Mac。需要 Mac 包就在 macOS 或 macOS CI runner 上构建。

### 发布 CI

仓库本身没有附带工作流：在 macOS 上 `npm run release` 一次就能同时拿到 mac 与 win 两套安装包，暂时没有 CI 也能发布。若要接 CI，思路是 `macos-latest` 跑 `npm run dist:mac`、`windows-latest` 跑 `npm run dist:win`，把 `dist/` 上传到 Actions Artifacts 或附到 Draft Release。

## 常见问题

**Q：输入房间码后一直「连接中」或提示找不到房间。**
先确认对方已点「创建房间」、两台设备在同一网段（路由器同一 Wi-Fi，且没开 AP 隔离），以及主机防火墙放行了应用（macOS 点「允许」；Windows 安装包已自动加规则）。应用会自动做广播 + 单播三重探测；如果「附近的房间」里看得到对方、按码加入却失败，多半是**房间重建过或抄错了一位**——新版会自动重扫并在报错里列出当前实际开着的房间，照着列表点「加入」即可；附近列表条目 90 秒自动过期。彻底找不到时，用「高级 → 手动地址」填 `主机IP:数据端口`（地址显示在主机界面第 1 步下方的「连不上？手动输入地址」里，可一键复制）。

**Q：对方能连上，但传输失败 / 校验不一致。**
多为无线链路抖动。重试一次；若反复失败，把设备靠近路由器，或改用有线。失败的文件不会留在保存目录（只删 `.part` 临时文件，不动已有文件）。

**Q：能传文件夹吗？会不会覆盖同名文件？**
能，保留目录层级递归传。同名不会覆盖，接收方自动改名成 `报告 (1).pdf`，依此类推。

**Q：文本能传多大？收到的文本在哪复制？**
第 4 步「传送文本」单条上限 **32 KB**（按 UTF-8 字节算），「仅文本发送」即时出现在对方的文本栏，点每行右侧的「复制」即可复制全文；「生成 TXT 发送」则走普通文件流程，落成对方保存目录里的一个 `.txt`。文本记录两端各保留最近 60 条，应用重启后清空。

**Q：能同时传给多台设备吗？**
可以，一个房间最多 8 台设备，在「发送到」里多选即可，逐台串行推流。

**Q：Mac 和 Windows 之间传文件名有讲究吗？**
有。发送前会按 Windows 的非法字符与保留名规则净化文件名，所以 Mac → Win 不会出现无法创建的文件；反之也安全。

**Q：需要登录账号吗？文件会上传到云上吗？**
不需要账号。局域网模式下没有任何云端组件，整个流程只有同网段的 UDP 探测和两台设备之间的 TCP 直连。跨网段传输是**可选**功能：只有你自己在设置里开启并填了中继地址，应用才会连你那台中继（Cloudflare / Vercel / 自建），中继只做字节透传、不落盘、不记日志，但它能看到明文内容——见[隐私提醒](#隐私提醒)。

**Q：两台设备不在同一个 Wi-Fi（一个家里一个公司）能传吗？**
能，用跨网段传输：两边都在主界面的「跨网传输」卡片里选 Cloudflare 或 Vercel 并填同一个中继地址，房主这边房间会挂上中继（设备列表出现「互联网中继」标记），访客直接输房间码加入，之后和局域网传文件完全一样。中继要自己部署一次，步骤见 [relay/README.md](relay/README.md)；不想部署就用本机 ngrok 隧道。

**Q：填了中继地址后一直「连接中」/ 报「中继上没有这个房间」。**
先点「测试连接」：报超时或连不上说明地址/网络有问题（域名拼错、服务商选错、企业代理拦截、Worker 还没部署）；能连通但报 `no-host` 说明**房主那侧**没挂上来——确认对方也开了跨网传输、房间码一致，且中继地址两边填的是同一个。详细排错表在 [relay/README.md](relay/README.md)。

**Q：Vercel 中继为什么「有时能连有时不能」？**
Vercel 的 Function 是多实例的，一条连接固定落在某个实例上，房主的槽位和访客的请求被分到不同实例时就配不上对（表现为 `no-host`）。这不是配置错误，是平台模型限制——稳定使用请选 Cloudflare（Durable Objects 按房间码强一致路由）或自建中继。

**Q：跨网传输一定要自己部署中继吗？**
不一定。这台电脑上装了 ngrok 的话，服务商列表里会出现「ngrok · 本机隧道」：点「启动隧道」就能拿到一条公网 https 地址，把它发给对方、对方粘进「自建 / 其它」的中继地址即可，一次部署都不用。详见[不想部署中继：用本机 ngrok 隧道](#不想部署中继用本机-ngrok-隧道装了才出现)。

**Q：跨网传输卡片里怎么没有「ngrok · 本机隧道」这一项？**
应用只在**真的在这台电脑上找到 ngrok** 时才把这一项和隧道面板画出来（找不到时界面和以前一模一样，不会留一个点不动的按钮）。找的顺序是 `PATH` → 各平台常见安装目录（macOS：`/opt/homebrew/bin`、`/usr/local/bin`、`/opt/local/bin`；Windows：`%LOCALAPPDATA%\ngrok`、`%ProgramFiles%\ngrok`、scoop、Chocolatey）。装好 `brew install ngrok` / `winget install ngrok.ngrok` 后**重启隔空传**再看。已经装到别的路径、或者装完没重启过应用，都可以先确认 `ngrok version` 在终端里能跑通（需要 3.x，1.x/2.x 的参数不一样会被判成「版本太旧」）。

**Q：ngrok 隧道每次地址都变，能不能固定？**
能。ngrok 免费账号也能在 [ngrok 控制台 → Domains](https://dashboard.ngrok.com/domains) 领到一个保留域名（形如 `abc123.ngrok-free.app`），把它填进隧道面板的 **「固定地址（可选）」** 再启动隧道，以后每次都是同一条地址，对方粘一次就能长期复用。填自己想的子域名或别人名下的域名会被 ngrok 拒掉（`ERR_NGROK_313` 等），界面会直接翻成中文告诉你只能用自己领到的那一个。隧道运行中输入框是锁住的——改域名要先「停止隧道」再起。

**Q：点了「启动隧道」却报「ngrok 未登录」/ 报一串英文。**
应用会把 ngrok 的英文报错翻成中文并把下一步写清楚：没登录时报的就是 `ngrok config add-authtoken <token>`（token 在 ngrok 控制台右上角 Your Authtoken）；报「同时只能开一条隧道」说明本机已有别的 ngrok 在跑，先停掉那条；报「检查端口被占用」说明 4040 被别的程序占了，应用会改从 ngrok 自己的日志里读它实际换用的端口，一般不会失败；报证书/代理相关错误通常是企业网络在 TLS 中间做了拦截。

**Q：浏览器打开 `http://localhost:47810/` 以前只有两个字，现在能看到什么？**
现在那是本机传输面板的入口之一。应用启动时会额外开一个只监听 `127.0.0.1` 的面板端口（默认 `47830`，设置里能看到实际地址），房间的数据端口（`47810`–`47822`）也挂同一份页面，两个地址在本机浏览器打开效果一样：概览、每条在传任务的字节级进度与速率、逐文件明细、设备列表、历史记录、累计统计、引擎参数，右上角可切 5 种语言、可暂停刷新。局域网里其它机器打开这些地址仍然是过去的 `404 SkyDrop`。详见[本机传输面板](#本机传输面板)。

**Q：面板打不开，或者地址不是 47830。**
先看设置里的「本机传输面板地址」那一行，以它为准——`47830` 起被占用时会顺延（最多试 13 个端口）。若那一行是空的，说明面板服务没起来（端口段全被占用），重启应用即可。确认是用**这台电脑自己的浏览器**打开：从别的机器访问、或者用容器/虚拟机里的浏览器访问 `localhost`，都拿不到数据。

**Q：面板能改设置、批准加入或者发起传输吗？**
不能，它只读。所有写操作仍然只在应用窗口里——网页上没有任何按钮会改动引擎状态。

**Q：同一局域网里的另一台电脑能打开我的面板吗？**
不能。面板端口只绑 `127.0.0.1`，其它设备连不上；房间数据端口虽然绑 `0.0.0.0`（文件传输需要），但对非回环来源一律返回 `404 SkyDrop`。本机上某个把域名解析到 `127.0.0.1` 的第三方网页也读不到数据，`Host` 头白名单会拦掉。

**Q：保存目录在哪？能改吗？**
默认 `~/Downloads/隔空传`（Windows：`%USERPROFILE%\Downloads\隔空传`）。设置面板里可改成任意目录。

## 已知限制

- 传输未加密，仅限可信局域网；走中继时中继运营方能看到文件名与文件内容（端到端加密是后续项，当前版本未实现）。
- 跨网段传输需要自己部署中继；Vercel 版不保证跨实例配对，且受 Function `maxDuration`（本仓库设为 300 秒）限制，长时间空闲的连接会被平台回收——跨网挂长时间「等人点接收」建议用 Cloudflare 或自建。
- ngrok 模式依赖**这台电脑上另外装好的 ngrok 3.x**（应用不内置 ngrok 二进制，也不替你注册账号）：没装就没有这个入口；免费版每次分配的公网域名都不一样、同时只能开一条隧道——不填「固定地址」时这条地址只适合现场发给对方，不能当固定入口（免费账号也能在 ngrok 控制台「Domains」领一个保留域名，填进「固定地址（可选）」后每次都是同一个入口）；隧道只在本机运行期间存在，退出应用即收掉 ngrok 子进程与内置中继。
- 走中继时所有字节都经过中继（两跳），速率取决于中继的出口带宽与免费额度（Cloudflare / Vercel 免费层都按流量计费/限额）；能走局域网时应用始终优先直连。
- 没有断点续传：中断后需重传整个文件。
- 没有多播同时分发（对多台设备是逐台串行推流）。
- 房间码是临时凭据，重启应用即失效，不做长期固定房间。
- macOS 包未签名/未公证，首次打开需手动放行；企业 MDM 环境可能仍需 IT 加白。
- Linux 未打包（引擎本身平台无关，`electron-builder` 加一个 `AppImage` target 即可）。
- 超大目录（>5000 文件）会被拒绝，避免句柄与内存压力。
- 单条文本上限 32 KB（UTF-8 字节）；「传送文本」列表只保留最近 60 条且只存内存，重启应用即清空。
- 本机传输面板的数据全在内存：历史记录只保留最近 60 条，重启应用即清空，面板不提供导出，也不落任何日志文件。
- 面板没有登录/令牌概念，靠的是「只有本机能够连上这个端口」这一条边界——同一台电脑上的其它进程与用户能读到同样的 JSON。不适合在多人共用的终端上把它当隐私边界，需要时直接关掉应用即可。
